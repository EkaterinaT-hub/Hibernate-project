- демо проект на базе  дамп
- Типичный запрос без оптимизации может приводить к проблеме N+1
2. 
3. Решение
- Выгружаем агрегатированные данные в Redis

- Приложение обращается сначала к Redis и только при отсутствии данных - к БД

- Технологический стек:
    - Java 17
    - Maven
    - Hibernate
    - MySQL
    - Redis
    - P6Spy
    - Docker

- Domain:
    - City
    - Continent
    - Country
    - CountryLanguage
  
- DAO - методы получения данных из MySQL
- Redis DTO - класс CityCountry (плоская структура, готова для кэша)
- Загружаем данные из MySQL, трансформируем в DTO, сохраняем в Redis, тестируем чтение

3. Окружение
   docker run --name mysql -e MYSQL_ROOT_PASSWORD=root -d -p 3306:3306 restsql/mysql
   docker run -d --name redis -p 6379:6379 redis:6.2-alpine

4. Апгрейд проекта

1) Предметная область: страны, города, языки
2) Связи: @OneToMany страна -> языки, @ManyToOne город -> страна, @OneToOne страна -> столица.
3) Проблема N+1: с городами и странами
4) Кэшируемые данные: CityCountry(id города, название, население, данные страны, список языков)
5) Трансформация: City -> CityCountry
6) Ключ в Redis: <id города>
7) Тестирование: два теста, сравниваем время
